5. PLUGIN ENABLEMENT (probe for Task 6, same scratch repo)
================================================================================

Embedded doc `assets/external/skills/agy-customizations/docs/plugins.md` (also on disk at
`~/.gemini/antigravity-cli/builtin/skills/agy-customizations/docs/plugins.md`), verbatim:

  Most discovered plugins are **enabled by default**; a plugin can ship switched off by declaring
  `"disabled": true` in its `plugin.json`, and some built-in ones do. Whether a plugin is active is
  recorded in your `config.json`, under a `plugins` map keyed by the plugin's **directory** name:
  { "plugins": { "my-plugin": { "enabled": false } } }
  ... `config.json` wins wherever it has an entry, so your choice always beats what the plugin
  declares. ... A disabled plugin still appears in the plugin list so you can turn it back on, but
  none of its bundled customizations are loaded.

Empirical A/B in `/tmp/agyprobe/repoA/.agents/plugins/` (each plugin one SKILL.md whose
description mentions "plugin", then one model turn asking for the skill names from the skills
section):

  plugprobe-off/plugin.json = {"name":"plugprobe-off","disabled":true}   skill offskill
  plugprobe-on/plugin.json  = {"name":"plugprobe-on"}                    skill onskill
  plugprobe-en/plugin.json  = {"name":"plugprobe-en","enabled":false}    skill enskill

  run 1 -> "agy-customizations, onskill"
           (offskill absent: plugin.json "disabled": true IS honoured)
  run 2 (with plugprobe-en added) -> "enskill, onskill"
           (enskill present: plugin.json "enabled": false is IGNORED)

So: `disabled: true` = off, `enabled: false` = on. The plugin's current code (checks
`disabled: true`) matches the CLI.

MCP "needs configuration variables" (changelog 1.2.11: "a plugin whose MCP server needs
configuration variables now starts disabled until you enable it"): hand-placed global plugins
under `~/.gemini/config/plugins/<name>/` with mcp_config.json placeholders
`${VAR}`, `{{VAR}}`, and a `variables` map on the mcpServer entry produced NO new entry in
`~/.gemini/config/config.json` after `agy agents` and after a full print-mode turn
(`plugin_data/<name>/` was created, so the plugin manager did load them). Exact trigger NOT
determined. The mcp server config schema does carry a `variables` field
(`json:"variables,omitempty,omitzero"` / `yaml:"variables,omitempty"` / `mapstructure:...`), so
[INFERENCE] that is the declaration the CLI keys off, and the disabled state would be recorded as
`~/.gemini/config/config.json` -> `plugins.<dirname>.enabled: false` per the doc quoted above.
The user's own config.json already uses that shape (`"superpowers": { "enabled": false }`).
