`--mode plan` needs slash-command expansion to be on (that is what the warning is about), and with
expansion on the CLI writes a plan artifact, approves its own review — nobody is there to answer it
in a headless run — and then implements inside the same turn. The `--mode plan` runs ended with:

  "I have created the implementation plan … Please review the plan and approve it so I can
   proceed with creating a.txt.\nThe task has been completed:\n\n- Created a.txt with the content
   `hello`."

That happened with the `<plan_mode>` preamble in front of the prompt, and with and without
`--dangerously-skip-permissions` (the machine's own `toolPermission` is `always-proceed`). Without
expansion, the same prompt plans and stops under both policies, which is why the plugin keeps
expansion off and Paseo's plan mode is its own preamble rather than `--mode plan`.

Slash-command expansion, for the turn shape the plugin sends (no plan mode, expansion ON) — probed
the same day:

  `/skills`  → exit 2, `error: /skills is answered by the CLI itself and is unavailable with
               --input-format stream-json`

               list); pass --disable-slash-commands to send /tasks to the model as literal text`
  `/tmp/foo is a path …` → runs: only a name the CLI knows is expanded, not every leading `/`
  ` /skills` (leading space) → still expanded: the CLI trims the space first
  `\/skills`, `//skills`, `\u200b/skills` → run, unexpanded, and the escape is left in the text

Only the first token of a message is looked at: the same `/skills` after the `<plan_mode>` preamble
ran unexpanded (exit 0), which is why no escape is added to plan-mode prompts.
